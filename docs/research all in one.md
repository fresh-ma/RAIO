# Research All-in-One（RAIO）需求细化稿

版本：v0.2  
依据：当前手稿、README、`src/main.tsx`、`server.mjs`  
目标：把 RAIO 从想法手稿整理成可评审、可开发、可验收的产品需求文档。

## 1. 项目定位

RAIO 是一个面向科研人员，尤其是本科高年级、硕士、博士和科研助理的像素风科研陪伴 Web 应用。它不是单纯的效率面板，而是把论文检索、学习规划、待办管理、情绪记录和科研陪伴组织成一个有 Agent 人格的“小镇式”工作空间。

核心价值：

- 降低科研信息整理成本：帮助用户找论文、收藏论文、做阅读笔记、生成文献地图。
- 降低学习启动成本：围绕一个主题生成阶段化学习路径、教程和测验。
- 降低科研日常失控感：管理 Todo、记录心情、用轻量游戏化反馈维持节奏。
- 提供情绪陪伴：用温暖但不过度拟人的 Agent 反馈缓解科研孤独感。

一句话产品描述：  
RAIO 是一个像素风科研搭子，帮科研人读论文、做计划、学技术、记生活。

## 2. 目标用户与典型场景

### 2.1 目标用户

- 学生科研人员：本科毕设、硕博生、科研助理。
- 初入某个方向的研究者：需要快速了解领域、搭建知识框架。
- 多任务科研用户：同时处理论文、实验、课程、组会、申请或项目。
- 高压科研用户：需要记录情绪、分解任务、维持长期节奏。

### 2.2 典型场景

- 用户想入门一个方向，例如“扩散模型医学图像分割”，希望系统给出学习路径和代表论文。
- 用户输入关键词，希望从 arXiv 找到论文，并知道哪些论文更值得优先读。
- 用户读完论文后希望记录 Markdown 笔记，并让大模型帮助批注、总结和提问。
- 用户每天记录科研 Todo，完成后获得花园成长和成就反馈。
- 用户情绪低落或被拒稿后，希望有一个温和、具体、不说教的回应。

## 3. 产品原则

- 学术严谨：论文、新闻、学习资源必须标明来源；AI 生成内容必须避免伪造引用。
- 轻量可用：第一次打开就能体验核心功能，配置成本尽量低。
- 情绪价值服务于效率：像素风、成就、花园不是装饰，而是帮助用户建立长期节奏。
- 不过度承诺：学习路径是辅助规划，不宣称“几小时精通”或替代系统学习。
- 隐私优先：用户笔记、心情、服务器信息、API Key 和密码必须谨慎处理。

## 5. 功能需求

### 5.1 登录注册

目标：支持多用户使用，并为收藏、笔记、Todo、成就、学习记录提供数据隔离。

注册规则：

- 用户名：3-5 个英文字符，只允许大小写字母。
- 密码：8-15 位，必须同时包含字母和数字。
- 注册时必须二次确认密码。
- 用户名不可重复。

登录规则：

- 用户名和密码匹配后进入系统。
- 密码必须加密存储，禁止明文保存。
- 登录态可使用 session 或 token，过期策略后续确定。

验收标准：

- 输入非法用户名时提示规则。
- 两次密码不一致时不能注册。
- 重复用户名不能注册。
- 数据库中不能出现明文密码。

### 5.2 个人信息页面

目标：让用户建立自己的科研小镇身份。

字段：

| 字段 | 说明 |
| --- | --- |
| 用户 ID | 默认等于用户名，支持修改，需唯一 |
| 头像 | 提供默认像素头像，也支持上传 |
| 工作地点 | 提供预设地点，支持自定义后缀 |
| 邮箱 | 仅记录，不做验证 |
| 研究方向 | 可选，用于优化论文推荐和学习路径 |
| 入驻日期 | 用于计算 Day X |

工作地点示例：

- 鹈鹕镇的孵蛋大学
- 巫婆沼泽的五道口技术学院
- 法师塔的实验室
- 矿井深处的服务器房

验收标准：

- 用户能修改并保存个人资料。
- 上传头像有大小和类型限制。
- 邮箱可为空，但填写时需要基本格式校验。

### 5.3 首页

目标：作为 RAIO 的中央广场，汇总科研状态并提供 Agent 聊天入口。

核心模块：

- 中央 Agent 聊天窗口：用户可直接向 Agent 提问。
- 状态概览：收藏论文数、未完成 Todo 数、学习进度、星星余额。
- Todo 摘要：显示近期未完成任务，支持快速完成或跳转 Life 页面。
- 成就公告栏：展示已解锁成就；未解锁成就默认隐藏或显示为“神秘成就”。
- Agent 入口：Paper、Learn、Life、News、Server 的快速入口。

当前项目说明：

- 已实现中央聊天、状态卡片、Agent 入口、成就公告栏。
- Todo 添加目前在 Life 页面，不在首页。
- 成就解锁条件目前是可见的，不符合“隐藏成就”的原设想。

验收标准：

- 首页能看到用户当前科研状态。
- 用户能从首页进入所有核心模块。
- 聊天失败时有可用的本地兜底回复。

### 5.4 图书馆页面 Paper

目标：帮助用户完成从“搜索论文”到“形成阅读计划”的闭环。

#### 5.4.1 论文搜索

用户输入关键词或自然语言研究问题，系统调用 arXiv API 返回论文结果。

最低要求：

- 返回 3-5 篇高相关论文。
- 每篇论文展示标题、作者、发布日期、摘要、arXiv 链接。
- 链接能跳转到原网页。
- 支持收藏到个人图书馆。

增强要求：

- 对用户问题进行查询拆解，例如主题词、benchmark、survey、limitation。
- 生成文献地图：主要技术路线、经典论文、代表性方法、后续学习建议。
- 标注 AI 总结与真实元数据的区别，避免把模型生成内容当作真实引用。

学术严谨要求：

- 论文标题、作者、摘要、链接必须来自 arXiv 返回结果。
- “经典论文”“开山之作”“里程碑论文”不能仅凭模型猜测，至少需要可核验来源。
- 如果没有可靠依据，应表述为“可能值得关注”或“建议进一步核验”。

当前项目说明：

- 已通过本地 Node 代理调用 arXiv，并返回论文列表。
- 已有文献地图和论文问答。
- 当前默认最多返回 10 篇，不是手稿要求的 3-5 篇。
- 已有 Paper Vault 收藏书架。
- 尚未实现论文删除、标签、独立笔记页、Markdown 下载。

#### 5.4.2 个人图书馆

用户可把搜索结果收藏到个人图书馆。

功能：

- 收藏论文。
- 删除收藏。
- 给论文添加标签。
- 进入论文详情页。
- 写 Markdown 阅读笔记。
- 调用大模型对笔记进行总结、批注、生成问题。
- 下载笔记为 `.md` 文件。

验收标准：

- 收藏后刷新页面仍保留。
- 删除论文后不再出现在收藏列表。
- 笔记内容支持 Markdown 保存。
- 下载文件名包含论文标题或 arXiv ID。

### 5.5 八卦早知道 News

目标：给科研用户一个低负担的信息入口，区分普通新闻和学术新闻。

内容来源：

- 普通新闻：国内外新闻源，优先使用官方 RSS 或公开 API。
- 学术新闻：Nature、Science、MIT News、Google AI Blog、OpenAI Blog、arXiv 相关趋势等可公开访问来源。

功能：

- 展示少量高价值新闻，不做信息流沉迷。
- 学术新闻优先展示。
- 每 8 小时更新一次，更新间隔做成配置变量。
- 每条新闻必须包含标题、来源、时间、链接。
- AI 可生成 1-2 句摘要，但必须标注“AI 摘要”。

风险与限制：

- 不建议直接抓取网页全文，需注意版权和站点条款。
- 不应混淆新闻事实与模型评论。
- 对高风险新闻内容不做未经核实的结论。

当前项目说明：

- 未实现 News 页面。

验收标准：

- 能展示至少 2 类新闻：普通新闻、学术新闻。
- 手动刷新和自动刷新都可用。
- 没有网络时显示上次缓存内容或明确错误提示。

### 5.6 大师之路 Learn

目标：围绕用户输入主题生成学习路径，并通过教程、练习和测验帮助用户持续推进。

推荐表述：  
不要写“几小时精通”。更严谨的目标是“帮助用户快速建立学习路径，并完成可验证的入门训练”。

核心流程：

```text
[首页或 Learn 页面] 输入学习主题
    ↓
[AI 生成] 5-7 个章节，包含难度、预计时长、知识点标签
    ↓
[课程路径页] 可视化章节列表，显示完成进度
    ↓
用户点击某章节
    ↓
[课程内容页] 展开讲解：知识点、练习、论文/博客/视频资源
    ↓
用户点击“开始测验”
    ↓
[测验页] 生成 4 道选择题，用户逐题作答
    ↓
提交
    ↓
[结果页] 成绩、逐题解析、复习建议、下一章建议
    ↓
返回课程路径页，章节标记为已完成或需复习
```

章节内容要求：

- 学习目标。
- 前置知识。
- 核心概念。
- 关键公式或机制。
- 示例或最小实践。
- 推荐资源：可包含 Bilibili、YouTube、论文、博客、代码仓库。
- 测验：全部为选择题，便于快速作答和自动判分。

历史记录：

- 每个用户学过的主题都应保留。
- 用户可继续上次进度。
- 已完成章节、测验成绩、复习建议需要保存。

当前项目说明：

- 已实现学习路径生成。
- 已实现阶段教程弹窗。
- 已实现阶段完成与复盘点评。
- 测验目前是文本复盘，不是 4 道选择题。
- 只保存一条当前学习路径，未实现多主题历史。
- 尚未接入真实视频资源搜索或资源校验。

验收标准：

- 输入“线性代数”能生成合理章节，例如行列式、矩阵、向量空间、特征值、线性变换。
- 每章有可读教程和可操作练习。
- 测验为选择题，提交后有分数和解析。
- 刷新页面后进度不丢失。

### 5.7 活着 Life

目标：用低压力方式帮助用户记录生活状态和科研节奏。

功能：

- Todo：添加、完成、删除、优先级、截止日期、类别。
- 心情记录：每日选择心情并写简短笔记。
- 花园：完成 Todo、记录心情、完成学习阶段后触发植物成长。
- 日历：显示未来 7 天任务。
- Agent 关怀：根据心情和任务压力给出简短建议。

当前项目说明：

- 已实现 Todo 添加、完成、优先级、截止日期、类别。
- 已实现周日历、心情记录、花园、Agent 回应。
- 尚未实现 Todo 删除。
- “浇水”等互动较弱，花园更像结果展示。

验收标准：

- 用户能添加和完成 Todo。
- 用户能删除误添加的 Todo。
- 用户能记录当天心情。
- 花园状态能持久保存。

### 5.8 成就与换装

目标：提供长期反馈，让科研生活有轻量成长感。

成就规则：

- 成就默认隐藏，仅显示已解锁成就。
- 可显示少量“神秘成就”占位，但不暴露具体条件。
- 成就解锁后给出公告。
- 成就可奖励星星，星星可用于解锁 Agent 装扮。

建议初始成就：

| 成就名 | 解锁条件 |
| --- | --- |
| 点亮图书馆 | 收藏第 1 篇论文 |
| 书架初成 | 收藏 5 篇论文 |
| 文献猎人 | 完成 10 次论文搜索 |
| 我就是天选打工人 | Todo 列表累计超过 7 个 |
| 今日也活着 | 第 1 次记录心情 |
| 温室常客 | 连续 7 天记录心情 |
| 新手村毕业 | 完成第 1 个学习阶段 |
| 大师之路开启 | 生成第 1 条学习路径 |
| 复盘使人进步 | 提交第 1 次学习测验 |
| 科研小镇居民 | 连续使用 7 天 |

当前项目说明：

- 已实现星星积分和换装面板。
- 已实现部分成就展示。
- 成就条件目前直接展示，且数量不足 10 个。
- 星星解锁逻辑偏简单，只按星星余额判断，不记录已购买状态。

验收标准：

- 用户完成指定行为后自动解锁成就。
- 已解锁成就刷新后仍保留。
- 星星消费和装扮解锁逻辑明确，不能出现重复扣费或越权穿戴。

### 5.9 Server Agent（建议保留）

说明：Server Agent 不在原手稿中，但当前项目已经实现，对科研用户尤其是深度学习用户很实用，建议作为增强模块保留。

功能：

- 粘贴 `nvidia-smi` 输出并解析 GPU 温度、显存、利用率。
- 通过本地代理执行安全 SSH 巡检命令。
- 屏蔽高危命令。
- 调用大模型生成诊断建议。

当前项目说明：

- 已实现本地 SSH 代理、命令安全拦截、GPU 解析、诊断建议。
- 需要补充更清晰的隐私提示和连接失败提示。

验收标准：

- 能解析常见 `nvidia-smi` 输出。
- 密码不持久化保存。
- 高危命令会被阻止。


大模型相关接口：

- 前端不能直接暴露 API Key。
- 所有大模型调用必须经过后端代理。
- 后端从 `.env` 读取密钥。
- 接口需要限制输入长度，避免异常请求和成本失控。

## 8. 技术路线

### 8.1 原手稿目标技术路线

- 前端：React。
- 后端：Python FastAPI。
- 数据库：MySQL。
- 配置：API Key 存入 `.env`。

### 8.2 当前项目实际技术路线

- 前端：React 18 + TypeScript。
- 后端：Node 本地代理 `server.mjs`。
- 数据存储：浏览器 `localStorage`。
- 大模型：华为 MaaS OpenAI-compatible 接口。
- 论文搜索：Node 代理调用 arXiv API。
- 服务器模块：Node + `ssh2`。

### 8.3 符合度结论

当前项目已经符合“像素风科研 Agent 原型”的主要方向，但不符合“完整多用户 Web 产品”的技术路线。

如果目标是课程展示或本地 Demo：

- 保留当前 Node 代理和 localStorage 是合理的。
- 优先补齐 Paper 笔记、Learn 选择题、Life 删除 Todo、News 页面。

如果目标是完整项目或长期部署：

- 需要引入 FastAPI 和 MySQL。
- 需要实现登录注册、用户数据隔离、密码加密、文件上传。
- 需要把 localStorage 状态迁移到数据库。

## 10. 建议开发优先级

### P0：先把当前原型补成闭环

- 个人信息。

- 引入 FastAPI。

## 11. MVP 验收清单

一个可展示 MVP 至少应满足：

- 用户能进入首页，与中央 Agent 聊天。
- 用户能搜索 arXiv，并收藏论文。
- 用户能为收藏论文写 Markdown 笔记并下载。
- 用户能输入学习主题，生成学习路径。
- 每个学习章节有教程和 4 道选择题。
- 用户能添加、完成、删除 Todo。
- 用户能记录心情，花园随行为变化。
- 用户能解锁至少 10 个成就。
- API Key 不出现在前端代码。
- 页面刷新后核心数据不丢失。

完整版本还应满足：

- 支持注册和登录。
- 用户数据存入 MySQL。
- 密码加密存储。
- 支持个人资料编辑。
- 支持 News 页面 8 小时更新。
- 支持多用户数据隔离。
